# Интеграция заказов checkout → 1С (ручной ввод в конфигураторе)

Задача:
1. Раз в 3–5 минут забираем новые заказы по GET.
2. Создаем в 1С `Документ.ЗаказПокупателя`.
3. Отправляем обратно ack по PATCH (статус `processed` + ссылка на документ 1С).

Бэкенд endpoint-ы:
- `GET https://anette-gallery-frontend.vercel.app/api/v1/orders?limit=50&format=json&status=received`
  `Accept: application/json`
- `PATCH https://anette-gallery-frontend.vercel.app/api/v1/orders/{id}/ack`
  `Content-Type: application/json`

---

## Шаг 1 — Проверить, что конфигурация поддерживает HTTPS и JSON

Открой конфигуратор. Внизу в окне конфигурации:
- Платформа: должна быть 8.3.20 и выше (у нас 8.3.27 — подходит).

Мы используем стандартные объекты платформы:
- `HTTPConnection` / `HTTPRequest` / `HTTPResponse`
- `JSONReader` / `JSONWriter`

---

## Шаг 2 — Создать `Справочник.КлючИдентификатораЗаказовСайта`

Он нужен, чтобы не создавать один и тот же заказ дважды, даже если сайт повторно вернет `received`.

В конфигураторе:

1. В дереве конфигурации → правой кнопкой `Справочники` → `Добавить`.
2. Вкладка `Основное`:
   - Имя: `КлючИдентификатораЗаказовСайта`
   - Синоним: `Идентификаторы заказов сайта`
   - Длина кода: `36` (UUID)
   - Тип кода: `Строка`
   - Владелец: `Не использовать`
   - Иерархический: `Нет`
   - Периодический: `Нет`
3. Вкладка `Данные`:
   - Основной реквизит наименования: тип `Строка, длина 150`.
4. Добавить реквизиты:
   - `ДатаЗаказа` тип `ДатаВремя`
   - `СуммаЗаказа` тип `Число(18,2)`
   - `СсылкаЗаказаПокупателя` тип `ЛюбаяСсылка` (или конкретно `ДокументСсылка.ЗаказПокупателя`)
   - `СтатусОбработки` тип `Строка, длина 20` (значения: `new` / `processed` / `error`)
   - `КомментарийОшибки` тип `Строка, длина 0 (без ограничений)`
5. Сохранить (`Файл` → `Сохранить конфигурацию` или Ctrl+S).

---

## Шаг 3 — Создать обработку `Обработка.СинхронизацияЗаказовСайта`

В дереве конфигурации правой кнопкой `Обработки` → `Добавить`.

1. Имя: `СинхронизацияЗаказовСайта`
2. Синоним: `Синхронизация заказов сайта`
3. Закладки:
   - Вкладки: `Объект` (оставляем), убираем лишние.
4. Открываем `Модуль объекта обработки` (в дереве под обработкой → правой кнопкой `Открыть модуль объекта`).

Вставить в модуль объекта код из файла:
`onec/Обработка_СинхронизацияЗаказовСайта_МодульОбъекта.txt`

---

## Шаг 4 — Ручная проверка (первый запуск)

Перед тем как вешать на регламентное задание, проверить руками.

В конфигураторе:
1. `Отладка` → `Запустить в режиме Предприятия (клиент)`
2. Войти как Администратор
3. Найти обработку в пользовательском режиме:
   - Если интерфейс `Такси` / `1С:Предприятие 8.3`:
     - `Все функции` → найти `СинхронизацияЗаказовСайта` → открыть
   - Если нет — можно ввести в строку поиска по командному интерфейсу.
4. Нажать кнопку `Выполнить синхронизацию()` (из формы обработки — или через консоль разработчика вызывать, если добавил форму).

Результат ожидаемый:
- Заказы со статусом `received` создадутся как `Документ.ЗаказПокупателя`
- В справочнике появятся строки с `СтатусОбработки = "processed"`
- Сайт больше не вернет этот заказ по `status=received` (так как статус сменился на `processed`)

---

## Шаг 5 — Создать регламентное задание

В конфигураторе:

1. В дереве конфигурации → `Регламентные задания` → правой кнопкой → `Добавить`.
2. Вкладка `Основное`:
   - Имя: `СинхронизацияЗаказовСайта`
   - Синоним: `Синхронизация заказов checkout`
   - Ключ уникальности: любой уникальный UUID (сгенерировать в 1С или взять произвольный).
   - Количество повторов при ошибке: 3
3. Вкладка `Действие`:
   - Тип метода: `На сервере`
   - Метод:
     Выбрать обработку `СинхронизацияЗаказовСайта` → метод `РегламентноеЗадание_Выполнить()`
     Сигнатура должна быть без параметров.
4. Вкладка `Расписание`:
   - Тип периодичности: `секунды`
   - Повторять каждые: `300` (то есть 5 минут). Можно 180 = 3 минуты.
5. Сохранить.
6. В пользовательском режиме (не в конфигураторе!) зайти в `НСИ и администрирование` → `Общие настройки` → `Регламентные и фоновые задания` → убедиться, что это регламентное задание активно (`Включено = Да`), поле `Пользователь` заполнено (твой пользователь 1С).

## Шаг 6 — Настройки (константы/пароли)

В текущем варианте базовый URL захардкожен в константах внутри модуля обработки:

```bsl
Функция БазовыйURL() Возврат "https://anette-gallery-frontend.vercel.app"; КонецФункции
```

Чтобы не перекомпилировать код каждый раз, можно вынести это в `Константа` конфигурации:

1. В дереве конфигурации → `Константы` → `Добавить`.
2. Имя: `URLСайтаЗаказовCheckout`, тип `Строка`, длина 200.
3. По аналогии:
   - `ТаймаутСайтаЗаказовCheckout` тип `Число(6,0)` (секунды)
   - `СКУПоУмолчаниюДляНеизвестногоТовара` тип `Строка, 50`

И в обработке заменить хардкод на чтение констант:

```bsl
БазовыйURL = Константы.URLСайтаЗаказовCheckout.Получить();
```

## Шаг 7 — Сопоставление товара по SKU (артикулу)

В текущем коде используется функция:

```bsl
Функция НайтиНоменклатуруПоАртикулу(Артикул)
```

Она ищет в `Справочник.Номенклатура` по реквизиту `Артикул`. Если в твоей конфигурации это поле называется иначе (например, `Код`, `АртикулТовара`, `АртикулНоменклатуры`) — замени имя реквизита в одной строке функции.

Если артикула нет — товар попадет как заглушка по умолчанию (нужно создать вручную одну номенклатуру с артикулом из константы).

---

## Шаг 8 — Поля ЗаказаПокупателя, если нет типовых

Если в твоей конфигурации `ЗаказПокупателя` нет стандартных полей (например, контрагент создается по телефону, способ доставки отдельный справочник, комментарий пишется в `Комментарий`), адаптируй функцию `СоздатьЗаказПокупателя()`.

Главное — она должна вернуть два значения:
```
Возврат Ссылка, Номер;
```
Потому что именно они идут в ack PATCH запрос.

---

## Схема повторных запусков

1. Регламент задание вызывает `Обработка.СинхронизацияЗаказовСайта.РегламентноеЗадание_Выполнить()`
2. Метод делает `GET` до 50 заказов `status=received`
3. Для каждого заказа:
   - если нет в справочнике ключей → создать справочник
   - создать `ЗаказПокупателя`
   - сделать `PATCH /ack` со статусом `processed`
   - обновить справочник ключей на `processed` и указать ссылку на документ
4. Если заказ уже есть в справочнике и `processed` — он просто игнорируется
5. Если создание упало с ошибкой — в справочнике статус будет `error` и комментарий, а ack не отправится, чтобы можно было запустить повторно.
